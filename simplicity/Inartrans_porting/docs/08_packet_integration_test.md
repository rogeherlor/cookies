# Packet Integration Test

## Purpose

The packet integration test verifies that sensor data and navigation output can be converted into the legacy 75-byte packet format.

It extends the previous integration test by adding the `CookiePacketData` structure and the packet builder stage.

The goal is to validate the data flow up to packet generation, not radio transmission.

## What it tests

The test connects:

- GNSS parser
- Navigation module
- Mock EKF
- IMU sample
- IMU converter
- IMU preprocessor
- Packet data model
- Packet builder

## Test flow

    Fake GNSS data
            ↓
    GNSS parser
            ↓
    Navigation update
            ↓
    Mock EKF initialisation/update

    Fake IMU data
            ↓
    IMU sample
            ↓
    IMU converter
            ↓
    IMU preprocessor
            ↓
    Navigation prediction
            ↓
    Mock EKF prediction

    Navigation state + GNSS + IMU
            ↓
    CookiePacketData
            ↓
    Packet builder
            ↓
    75-byte legacy packet

## Expected behaviour

- GNSS data is parsed correctly.
- The navigation module waits for several valid GNSS fixes before initialising.
- The first IMU sample initializes the timestamp in the converter.
- The second IMU sample provides a positive `dt`.
- The navigation prediction step is executed.
- `CookiePacketData` is filled from GNSS, IMU and navigation outputs.
- The packet builder produces a 75-byte packet.
- Key legacy bytes are correctly set:
  - validity byte = `A`
  - GNSS mode byte = `7`
  - final legacy markers = `,,`

## What it does NOT validate

This test does not validate:

- Real EKF behaviour
- Physical navigation accuracy
- Real IMU hardware
- Real GNSS hardware
- UART input
- Radio transmission
- Network headers
- Simplicity Studio integration
- Packet reception or parsing

## Notes

The packet generated by this test preserves the legacy 75-byte layout.

The internal data is grouped cleanly in `CookiePacketData`, but the final packet keeps the old byte offsets for compatibility.

The final `,,` bytes are legacy markers from the original packet format. They are not a new end-of-packet mechanism.

# Test de integración del paquete

## Objetivo

El test de integración del paquete comprueba que los datos de sensores y la salida de navegación pueden convertirse al formato legacy de 75 bytes.

Extiende el test de integración anterior añadiendo la estructura `CookiePacketData` y el módulo packet builder.

El objetivo es validar el flujo de datos hasta la generación del paquete, no la transmisión por radio.

## Qué prueba

El test conecta:

- Parser GNSS
- Módulo Navigation
- EKF mock
- IMU sample
- IMU converter
- IMU preprocessor
- Modelo de datos del paquete
- Packet builder

## Flujo del test

    Datos GNSS simulados
            ↓
    Parser GNSS
            ↓
    Actualización de navegación
            ↓
    Inicialización/update del EKF mock

    Datos IMU simulados
            ↓
    IMU sample
            ↓
    IMU converter
            ↓
    IMU preprocessor
            ↓
    Predicción de navegación
            ↓
    Predicción del EKF mock

    Estado de navegación + GNSS + IMU
            ↓
    CookiePacketData
            ↓
    Packet builder
            ↓
    Paquete legacy de 75 bytes

## Comportamiento esperado

- Los datos GNSS se parsean correctamente.
- El módulo de navegación espera varios fixes GNSS válidos antes de inicializarse.
- La primera muestra IMU inicializa el timestamp del converter.
- La segunda muestra IMU proporciona un `dt` positivo.
- Se ejecuta la predicción de navegación.
- `CookiePacketData` se rellena a partir de GNSS, IMU y navigation.
- El packet builder genera un paquete de 75 bytes.
- Los bytes legacy principales se rellenan correctamente:
  - byte de validez = `A`
  - byte de modo GNSS = `7`
  - marcadores legacy finales = `,,`

## Qué NO valida

Este test no valida:

- Comportamiento del EKF real
- Precisión física de navegación
- Hardware IMU real
- Hardware GNSS real
- Entrada UART
- Transmisión por radio
- Cabeceras de red
- Integración con Simplicity Studio
- Recepción o parseo del paquete

## Notas

El paquete generado por este test conserva el layout legacy de 75 bytes.

Los datos internos están agrupados de forma limpia en `CookiePacketData`, pero el paquete final mantiene los offsets antiguos por compatibilidad.

Los bytes finales `,,` son marcadores legacy del formato original. No son un nuevo mecanismo de fin de paquete.
