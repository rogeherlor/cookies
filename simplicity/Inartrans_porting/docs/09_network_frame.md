# Network Frame

## Purpose

The network frame module builds the complete message that is ready to be transmitted over the network.

It wraps the 75-byte data packet with a 15-byte header, producing a 90-byte message that matches the legacy Inartrans_v2 format.

This module isolates the network structure from the rest of the system.

## Structure

The network frame is composed of:

    Header (15 bytes) + Payload (75 bytes) = Message (90 bytes)

### Header layout

| Bytes | Field            |
|------|------------------|
| 0    | Packet type      |
| 1–2  | Sender rank      |
| 3–4  | Destination      |
| 5–6  | PAN ID           |
| 7–8  | Source           |
| 9–10 | Packet number    |
| 11–12| Source rank      |
| 13–14| Sequence         |

### Payload

    Bytes 15–89 → 75-byte data packet

The payload is generated by the packet builder and is not modified by this module.

## Responsibilities

This module:

- Builds a complete network message
- Preserves the legacy header format
- Copies the payload into the correct position
- Keeps network concerns separated from data formatting

## What it does NOT do

This module does not:

- Send data over the radio
- Handle acknowledgements or retries
- Perform routing or networking logic
- Validate payload contents
- Modify sensor or navigation data

## Design rationale

The original system mixed:

- Packet formatting
- Network header construction
- Radio transmission

This module separates the network framing step to:

- Improve clarity
- Enable isolated testing
- Avoid tight coupling with hardware
- Preserve compatibility with the legacy format

## Example flow

    Sensor data
            ↓
    Navigation / EKF
            ↓
    Packet builder (75 bytes)
            ↓
    Network frame builder (90 bytes)
            ↓
    Ready-to-send message

# Trama de red

## Objetivo

El módulo de trama de red construye el mensaje completo listo para ser transmitido por la red.

Envuelve el paquete de datos de 75 bytes con una cabecera de 15 bytes, generando un mensaje de 90 bytes que coincide con el formato legacy de Inartrans_v2.

Este módulo aísla la estructura de red del resto del sistema.

## Estructura

La trama de red está compuesta por:

    Cabecera (15 bytes) + Payload (75 bytes) = Mensaje (90 bytes)

### Layout de la cabecera

| Bytes | Campo            |
|------|------------------|
| 0    | Tipo de paquete  |
| 1–2  | Rango del nodo   |
| 3–4  | Destino          |
| 5–6  | PAN ID           |
| 7–8  | Origen           |
| 9–10 | Número de paquete|
| 11–12| Rango origen     |
| 13–14| Secuencia        |

### Payload

    Bytes 15–89 → paquete de datos de 75 bytes

El payload es generado por el packet builder y no se modifica en este módulo.

## Responsabilidades

Este módulo:

- Construye el mensaje completo de red
- Mantiene el formato de cabecera legacy
- Copia el payload en la posición correcta
- Separa la lógica de red del formateo de datos

## Qué NO hace

Este módulo no:

- Envía datos por radio
- Gestiona ACKs o retransmisiones
- Implementa lógica de red o routing
- Valida el contenido del payload
- Modifica datos de sensores o navegación

## Razonamiento de diseño

El sistema original mezclaba:

- Formato del paquete
- Construcción de cabecera
- Transmisión por radio

Este módulo separa la capa de framing para:

- Mejorar la claridad
- Permitir testing independiente
- Evitar dependencias con hardware
- Mantener compatibilidad con el formato antiguo

## Flujo de ejemplo

    Datos de sensores
            ↓
    Navigation / EKF
            ↓
    Packet builder (75 bytes)
            ↓
    Network frame builder (90 bytes)
            ↓
    Mensaje listo para enviar
